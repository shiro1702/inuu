# Варианты: добавление мастер-классов

**Мастер-класс (МК)** в продукте — подтип **события** с записью/оплатой, местом и датой. В БД уже есть категория `event_categories.slug = 'masterclass'`.

---

## Что уже есть

```sql
events (
  city_id, venue_id?, shop_id?, category_id?,
  slug, title, description,
  starts_at, ends_at, capacity, price, currency,
  cover_media_url, is_promoted, is_published
)
```

- Seed-категория «Мастер-классы» в `019_inuu_seed_ulan_ude.sql`
- Demo-event `kids-workshop` без привязки к `category_id` (техдолг seed)
- API: `GET /api/cities/[slug]/events` (без фильтра по категории пока)
- UI страниц `events/[slug]` — в плане refactor, **ещё нет**

**Нет в схеме:** отдельные сессии одного МК, организатор как `organization_id`, билеты с QR, waitlist — см. verticals/events.

---

## Вариант 1 — Обычное событие с категорией `masterclass` (рекомендуемая модель данных)

**Суть:** один CRUD для всех типов афиши; фильтр на витрине `category_slug=masterclass`.

| Плюсы | Минусы |
|-------|--------|
| Одна таблица, один dashboard | Поля «вместимость/цена» не для всех типов |
| Уже в миграциях | Нужно проставлять `category_id` в UI |
| Фильтры «МК / концерт» из коробки | |

**Обязательные поля для МК:**

- `title`, `description`, `starts_at`, `ends_at`
- `venue_id` или адрес в description (лучше venue)
- `price`, `capacity` (если есть лимит мест)
- `category_id` → masterclass
- `cover_media_url`
- `shop_id` организатора (для dashboard)

---

## Вариант 2 — Отдельная таблица `masterclasses`

**Суть:** дублировать события в специализированную сущность с полями «материалы», «уровень», «возраст 6+».

| Плюсы | Минусы |
|-------|--------|
| Чистая доменная модель | Дублирование с `events`, двойной CRUD |
| | Сложнее афиша «всё в одном календаре» |

**Когда брать:** только если >30% полей уникальны для МК и не подходят `events` — **на MVP не нужно**.

---

## Вариант 3 — Новость + событие (двойная публикация)

**Суть:** редактор создаёт `events` (запись, билет) и `editorial_posts` (обзор/анонс с эмоцией и SEO).

| Плюсы | Минусы |
|-------|--------|
| SEO-статья + функциональная карточка | Два объекта, риск разных дат/цен |
| IG ведёт на статью, CTA на event | |

**Смягчение:** в dashboard кнопка «Создать анонс к событию» → автозаполнение post из event.

**Когда брать:** крупные МК с прогревом; для рутинных — только event.

---

## Вариант 4 — Кто создаёт: организатор vs редакция vs venue

| Роль | Сценарий | Интерфейс |
|------|----------|-----------|
| **Организатор** | Сам ведёт МК, продаёт билеты | Dashboard org: CRUD `events`, свои `shop_id` |
| **Редакция** | Партнёр прислал в DM, редактор заводит | Dashboard editorial: создать event от имени `shop_id` партнёра |
| **Venue** | Бар хостит чужих организаторов | Venue owner привязывает `venue_id`, организатор — `shop_id` |

**MVP-поток (минимум):**

1. Редакция/админ создаёт event в dashboard (вариант 4, редакция).  
2. Партнёрский доступ — **фаза 2** (заявка → approve).  

**RLS (целевое):** организатор пишет только `events` где `shop_id` ∈ его shops; публикация `is_published` — редактор или auto после модерации.

---

## Вариант 5 — Несколько сессий одного МК

**Суть:** один «МК по лепке» — 3 даты; сейчас = 3 строки `events` с разным `slug`.

| Подход | Плюсы | Минусы |
|--------|-------|--------|
| **5a. N строк events** | Без миграций | Дубли описания, сложно «серия» |
| **5b. `event_series` + `event_sessions`** | Одна карточка, выбор слота | Миграция + UI слотов |

**MVP:** 5a (несколько events с общим префиксом slug или полем `series_slug` позже).  
**После оплаты билетов:** 5b.

---

## Вариант 6 — Запись без оплаты (как beauty-слоты)

**Суть:** МК с `capacity`, запись через `bookings` type=event, цена 0.

Отличие от beauty: редкие слоты, разовые даты, не recurring schedule.

**Связь с кодом:** таблица `bookings` уже в roadmap refactor; до готовности — CTA WhatsApp / «Хочу пойти» (roadmap этап 1).

---

## Вариант 7 — Импорт из Instagram / Telegram

**Суть:** парсер поста → черновик event.

**Статус продукта:** явно **вне MVP** ([news-and-editorial.md](../../verticals/news-and-editorial.md)).

Имеет смысл только как полуручной assist: скопировать caption → форма в dashboard.

---

## Вариант 8 — Только подборка без карточки event

**Суть:** МК упомянут в `curated_list_items` + ссылка на внешнюю запись (TimePad, Google Form).

| Плюсы | Минусы |
|-------|--------|
| Мгновенно наполнить афишу | Нет аналитики, оплаты, «кто идёт» |
| | Противоречит гипотезе «запись на платформе» |

**Когда брать:** временно, пока нет checkout.

## Чеклист качества карточки МК

- [ ] Категория `masterclass` выставлена  
- [ ] `venue_id` заполнен (адрес на карте)  
- [ ] `starts_at` в timezone города (`Asia/Irkutsk`)  
- [ ] `capacity` если лимит мест  
- [ ] `price` и валюта (0 = бесплатно)  
- [ ] Обложка 4:5 или 16:9, < 500 KB  
- [ ] После МК — опционально `editorial_posts` «как прошло»
