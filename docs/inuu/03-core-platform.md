# Общая платформа (сквозной функционал)

Функции, общие для всех вертикалей INUU в рамках одного `city_id`.

---

## Главная страница города

- Витрина категорий: **события**, **красота**, **куда сходить** (venues), **отдых** (сезонно), **подборки**.
- Блок **Stories** (кружочки бизнеса + редакции).
- Блок **«Горит прямо сейчас»** (горящие окошки).
- Промо-баннеры (реклама, `is_promoted`).
- Поиск по всем категориям.

Дизайн: mobile-first, крупные фото, минимум текста, ЦА до 35 лет (Tailwind, компоненты Nuxt/Vue).

---

## Поиск и фильтры

### Глобальный поиск

- Названия: места, события, мастера, товары витрины брендов.
- Теги и категории.

### Типовые фильтры (по вертикали)

| Параметр | Beauty | Events | Venues | Tourism |
|----------|--------|--------|--------|---------|
| Рейтинг | ✓ | ✓ | ✓ | ✓ |
| Цена / бюджет | ✓ | ✓ | — | ✓ |
| Дата / ближайшее окно | ✓ | ✓ | — | ✓ |
| Район | ✓ | ✓ | ✓ | — |
| Вайб | — | тип МК | «для свидания» | «с баней», «вид на озеро» |

Реализация MVP: фильтры на клиенте (Vue + query) при <100 карточек; далее — `GET /api/...` + Supabase RPC / полнотекст.

---

## Карточка сущности (унифицированный шаблон)

- Hero-галерея (фото; первый слайд — опционально видео).
- Название, рейтинг, «мнение редакции» (цитата из Instagram-обзора).
- CTA: **Записаться** / **Купить билет** / **В избранное** / **Написать в WhatsApp**.
- Блок «Где»: адрес, карта, venue.
- Отзывы (после этапа 2).
- Связанные: другие события в этом venue; похожие места (позже).

---

## Избранное

- Типы: `venue`, `event`, `provider`, `master`, `story_collection`.
- Хранение: `user_favorites(user_id, entity_type, entity_id, city_id)`.
- ЛК: списки + фильтр по типу.
- **Будущие рассылки:** триггеры при новом событии в избранном venue, скидка у избранного мастера, категории интересов.

---

## Запись и заказы (единый движок)

Одна абстракция **Booking** с вариантами:

| Тип | Слот | Оплата |
|-----|------|--------|
| Beauty | Дата + время + мастер | Депозит / полная |
| Event | Дата + время + места | Билет |
| Confectioner custom | Дата выдачи + ТЗ | Предоплата |
| Confectioner stock | Количество + время выдачи | Полная / при выдаче |
| Tourism lead | Даты + гости + пожелания | Заявка без календаря (фаза 1) |

Статусы (базовые): `pending` → `confirmed` → `completed` / `cancelled` / `refunded`.

---

## События: билеты, слоты, холд

Для событий вводим два режима в одном домене:

1. **Классический event**: одна дата/время, типы билетов, лимит мест.
2. **Слотовый event (мастер-классы)**: несколько временных окон с отдельной вместимостью.

Базовые правила MVP:

- Лимит "в одни руки" на заказ (например, до 4 билетов).
- Временный холд места/билета на время оформления (`~15 минут`).
- Если оплата/подтверждение не завершены, холд снимается и места возвращаются.
- Бесплатные события проходят через тот же booking-flow без платежа.

Тикетная модель:

- `free` (регистрация, цена = 0),
- `paid` (платный билет),
- `tiered` (несколько тарифов/категорий в рамках события, фаза 2+).

Выдача после подтверждения:

- QR-билет в личный кабинет и в Telegram-бот.
- Статус использования билета проверяется на входе организатором через бот-сканер.

## Лист ожидания (Waitlist)

Сквозная фича для beauty и событий с лимитом мест.

1. Нет слотов → кнопка «Встать в очередь».
2. Параметры: желаемая дата/период, услуга, контакт.
3. При отмене записи — уведомление первому в очереди (или по приоритету).
4. Окно подтверждения **~30 минут**, иначе предложение следующему.
5. Каналы: Telegram, email, push (PWA).

Опционально позже: платный приоритет в очереди.

## Платежи

### MVP

- **ЮKassa** или **Тинькофф** — Nitro API + webhooks (см. [PAYMENTS_RU_YOOKASSA_TBANK.md](../payments/PAYMENTS_RU_YOOKASSA_TBANK.md)); паттерн как у `order.post.ts`.
- Оплата при бронировании beauty / билета на событие.
- Холд до оказания услуги (где применимо).
- **Возврат** при отмене по правилам (авто / ручная модерация).

### Не в MVP

- Интеграция с онлайн-кассой (54-ФЗ) — «пока не требуется».
- Модель: **сервис записи**, не полноценный маркетплейс с чеками на каждую сделку.

### Выплаты партнёрам

- Баланс исполнителя, периодический вывод (например, раз в неделю).
- На старте: только комиссия **банка**; платформенная комиссия 2–3% — после раскрутки.

## Отзывы и рейтинги

- Оценка 1–5, текст, фото (премодерация).
- Средний рейтинг на карточке.
- «Я здесь был» / чекин (фаза 2).
- Уведомление заведению о новом отзыве.

---

## Карта города

- Все `venues` + события с координатами.
- Кластеризация, фильтр по категории.
- Клик → карточка venue или список событий в точке.

---

## Stories (бизнес + редакция)

- TTL 24 часа (или ручное снятие).
- Загрузка: картинка / короткое видео ≤15 с (без встроенного редактора).
- CTA внутри story: ссылка на событие / акцию / горящее окно.
- Техника: Vue-компонент stories или zuck.js; загрузка в **Supabase Storage**; кампании в `dashboard/stories` (как у ресторанов).

**Не:** пользовательские stories и лента Reels.

---

## Страницы доверия

- О проекте, как работает запись и оплата.
- Оферта, политика конфиденциальности (152-ФЗ).
- Контакты, ссылки на соцсети редакции.

---

## Аналитика (сквозная)

- Счётчики: просмотры карточек, клики CTA, конверсия в запись.
- Дашборд партнёра: записи, доход, популярные услуги.
- Платформа: заказы по вертикалям, доход с рекламы, retention.

Инструменты: Яндекс.Метрика / GA + события в БД.
