Ограничения для отправки сообщения через бота не будет мешать стабильно работе? Если будет целый города на одном боте со всем функционалом?

Да, ограничения Telegram Bot API (лимиты на отправку сообщений) будут критической проблемой, если архитектура спроектирована неверно. Если запустить весь функционал целого города на одном боте «в лоб», бот начнет «засыпать», сообщения будут приходить с задержкой в несколько часов, а в худшем случае Telegram временно заблокирует бота за флуд.

Однако эту проблему можно полностью решить правильным проектированием архитектуры. Давайте разберем ограничения Telegram и то, как их обойти в вашем проекте.

Какие лимиты Telegram будут мешать?
Лимит 30 сообщений в секунду (Global Limit): Бот не может отправлять суммарно более 30 сообщений в секунду всем пользователям. Если в пятницу вечером 5000 человек одновременно ждут анонс выходных или статус заказа пиццы, возникнет огромная очередь.
Лимит 1 сообщение в секунду одному пользователю: Если бот отправляет клиенту статус заказа шаг за шагом слишком быстро, он получит ошибку 429 Too Many Requests.
Лимит 20 сообщений в минуту в одну группу/чат: Это критично для ваших чатов модераторов. Если парсеры сбросят туда 50 предложений по афишам за раз, бот зависнет.
Как решить эту проблему? (Архитектурные решения)
Чтобы бот работал стабильно на уровне целого города, вам нужно применить 4 тактических решения:

1. Разделение ботов (Мультибот-система)
Не используйте одного бота для всего. Разделите их по ролям. То, что для пользователя это «один сервис», под капотом может быть сетью ботов, привязанных к одной базе Supabase:

Бот №1: Главный городской бот (B2C). Он только запускает Mini App, выдает билеты и присылает важные транзакционные уведомления (заказы, покупки). У него минимальный текстовый трафик.
Бот №2: Технический бот модерации (B2B). Отдельный бот для парсеров и чатов модераторов. Если он словит лимит из-за наплыва спама от парсеров, обычные пользователи этого даже не заметят, и доставка еды продолжит работать.
Бот №3 (Опционально): Бот уведомлений для ресторанов. Присылает заказы владельцам заведений.
2. Перенос активности внутрь Mini App (Минимизация сообщений)
Поскольку у вас есть Telegram Mini App (TMA), не нужно общаться с пользователем текстом в чате бота.

Как делать не надо: Пользователь нажал «Посмотреть меню» -> бот прислал 10 сообщений с картинками блюд (это убьет лимиты).
Как надо: Пользователь нажал кнопку -> открылся Mini App (это веб-сайт на Nuxt 3). Все переходы по меню, выбор блюд, просмотр афиши происходят через HTTPS-запросы к вашему серверу Nitro, минуя серверы Telegram. Это вообще не тратит лимиты бота! Бот отправляет сообщение только ОДИН раз — чек и подтверждение заказа.
3. Внедрение очереди сообщений (Queue System)
В вашем сервере Nitro (или через Supabase Edge Functions) нельзя отправлять сообщения в Telegram напрямую по событию. Нужен посредник — Очередь (Queue).

Когда происходит событие (например, парсер нашел 100 событий), сообщения не отправляются сразу. Они записываются в таблицу базы данных telegram_queue.
Специальный фоновый процесс (воркер на Nitro) берет сообщения из этой таблицы и отправляет их в Telegram со скоростью не более 25 сообщений в секунду (безопасный порог).
Если лимит превышен, воркер делает паузу и продолжает отправку чуть позже, не роняя систему.
4. Использование каналов для массовых рассылок
Если вам нужно отправить новость или афишу на 10 000 человек:

Плохо: Делать рассылку ботом в личку каждому (это займет 6 минут и может забанить бота).
Хорошо: Вести официальный Telegram-канал города. Бот публикует один пост в канал (1 запрос к API), а пользователи читают его там. В личку бот пишет только по персональным триггерам (заказ, билет).
Резюме: Будет ли это работать стабильно?
Да, будет работать идеально, если вы разгрузите бота за счет Mini App.

Ориентация на mobile-first и референс Instagram в корне меняет правила игры. В мобильной версии у нас нет места для боковых панелей, а у пользователя нет мышки. Всё управление должно строиться на жестах (gestures), тапах и нижней выдвижной панели (Bottom Sheet).

Экран мобильного телефона условно делится на две зоны:

Верхняя зона (Просмотр): Сам холст (9:16 или 1:1).
Нижняя «Зона большого пальца» (Управление): Все кнопки, слайдеры и клавиатура должны быть здесь, чтобы до них было легко дотянуться одной рукой.
Вот подробный UX-проект мобильного редактора афиш в стиле Instagram.

1. Главный экран редактора (Анатомия интерфейса)
Экран выглядит максимально чисто, фокус — на вашей афише.

+-----------------------------------+
| [X] Назад       [🎨 Стили]  [💾]  |  <-- Шапка (минималистичная)
+-----------------------------------+
|                                   |
|        +-----------------+        |
|        |    КАТЕГОРИЯ    |        |
|        |   ЗАГОЛОВОК     |        |
|        |   [🔥 СТИКЕР]   |        |
|        |                 |        |
|        +-----------------+        |
|        Размер: 9:16 (Story)       |
+-----------------------------------+
|   [🤖 Спросить ИИ]   [🎨 Цвета]   |  <-- Быстрые действия (Thumb-zone)
+-----------------------------------+
| [ Текст ] [ Стикеры ] [ Шаблоны ] |  <-- Нижний таб-бар (Меню)
+-----------------------------------+
2. UX работы со стикерами (Absolute Items) в стиле Instagram
Работа со стикерами должна быть чисто тактильной. Пользователь управляет ими прямо на холсте пальцами.

Жесты на холсте:
Перетаскивание (Drag): Палец зажимает стикер и двигает его.
Масштаб и поворот (Pinch & Rotate): Двумя пальцами пользователь может крутить стикер и менять его размер (используем библиотеку типа hammer.js или interact.js для Vue 3).
Быстрое удаление (Капкан внизу): При начале перетаскивания стикера внизу экрана появляется иконка корзины 🗑. Если перетащить стикер туда — он удаляется (полная копия паттерна Instagram).
Инновационный мобильный UX для «Якорей» (Anchoring):
Когда пользователь тащит стикер и проносит его над текстовым блоком, телефон выдает короткую вибрацию (Haptic Feedback), а вокруг текста появляется мягкое свечение.
Если отпустить стикер в этой зоне, он «прилипает» (визуально соединяется с текстом). Теперь при изменении текста стикер не улетит.
Управление слоями (Z-Index) для мобилки:
Вместо сложных шкал, при тапе на стикер появляется контекстное мини-меню прямо под ним:

Кнопка «На задний план» (Под текст): Стикер уходит под буквы (z-index падает ниже текста).
Кнопка «На передний план»: Стикер ложится поверх букв.
Кнопка «Заменить» 🔁: ИИ предлагает 3 альтернативных стикера по этой же теме (например, меняет огонь на взрыв).
3. UX редактирования текста (Flow Items)
Большая проблема мобильных редакторов — клавиатура перекрывает половину экрана, и пользователь не видит, что пишет.

Как это решить (в стиле Instagram Stories):
Тап по тексту: Пользователь дважды тапает по заголовку или описанию на холсте.
Фокус-режим: Холст мгновенно размывается, а текст увеличивается и выносится в центр экрана над клавиатурой.
Ввод: Пользователь пишет текст.
Кастомизация «на лету»: Прямо над клавиатурой появляется горизонтальный скролл с выбором шрифтов и выравнивания (по левому краю, по центру).
Готово: Тап по пустому месту — текст возвращается на свое место в макете, размытие исчезает.
+-----------------------------------+
|  [Готово]     [A_шрифт]    [Left] | <-- Настройки шрифта
+-----------------------------------+
|                                   |
|        Романтический вечер        | <-- Текст в фокусе ввода
|                                   |
+-----------------------------------+
|  [ Й ] [ Ц ] [ У ] [ К ] [ Е ]    | <-- Клавиатура смартфона
|  [ Ф ] [ Ы ] [ В ] [ А ] [ П ]    |
+-----------------------------------+
4. Bottom Sheets (Нижние шторки) для выбора контента
Когда пользователь нажимает кнопку [+ Стикеры] или [🤖 Спросить ИИ] в нижнем меню, снизу плавно выезжает панель (Bottom Sheet), перекрывая нижнюю половину экрана. Это позволяет не уходить с экрана холста.

Нижняя шторка «Стикеры» (Интеграция с Groq):
Поисковая строка: «Поиск стикеров...»
Рекомендации ИИ (Умный блок): На самом верху шторки ИИ выводит плашки: «ИИ рекомендует для вашего концерта: [Icon: Гитара], [Icon: Звезда], [Icon: Огонь]».
Пользователь просто тапает по иконке, и она тут же появляется в центре холста.
Нижняя шторка «Генерация через Groq» (Magic Prompt):
Пользователь нажимает кнопку с иконкой ИИ (🤖 или 🪄).
Выезжает шторка с полем ввода: «Опиши своими словами, что за событие ты планируешь?»
Под полем ввода лежат готовые шаблоны-быстрые подсказки (Промпты в один тап):
[🎸 Концерт в баре]
[🍕 Открытие пиццерии]
[🧠 Лекция/Мастер-класс]
Пользователь нажимает [Концерт в баре], вписывает «Группа Кино, 30 декабря, вход свободный» и жмет «Создать магию». Шторка закрывается, на холсте появляется готовая афиша.
Резюме мобильного паттерна:
Холст неприкасаем: Он всегда виден, его не перекрывает клавиатура.
Всё через Bottom Sheets: Выбор стикеров, выбор стилей, генерация текста — всё выезжает снизу и закрывается свайпом вниз.
Два пальца для декора: Стикеры масштабируются и крутятся интуитивными жестами, как в Instagram Stories.
Умное прилипание (Snapping): Физический отклик (вибрация) при привязке стикера к тексту.
Такой UX будет ощущаться невероятно современным, быстрым и «дорогим», а пользователи смогут собирать стильные афиши буквально на ходу в метро.

Давайте разберем техническую архитектуру этой системы «под капотом». Мы обойдемся без кода и разберем логику процессов: как данные превращаются в картинку, как работает физика «прилипания» и как ИИ общается с холстом.

Всю техническую часть можно разделить на 4 главных движка (модуля), которые работают одновременно.

1. Древо Состояния (The State Tree) — Мозг системы
Вся афиша в любой момент времени — это просто текстовый документ (JSON), описывающий структуру. Это «единственный источник правды».

Этот документ разделен на две независимые зоны:

Поток (Flow Stack): Список элементов, которые идут строго друг за другом (как вагоны поезда). У них нет координат X и Y. У них есть только порядок (какой вагон за каким) и внутренние отступы.
Спутники (Satellites / Absolute items): Список элементов, у которых есть координаты. Но у каждого «спутника» есть важнейшее свойство — Родительский Якорь (Anchor Parent). Он указывает, к чему привязан спутник: к координатной сетке всего экрана или к конкретному «вагону» из первого списка.
2. Двухшаговый Движок Рендеринга (The Dual-Pass Renderer)
Как телефон понимает, где что нарисовать? Процесс отрисовки происходит в два шага:

Шаг 1: Отрисовка Потока (Flow Pass) Система сначала берет список «Поток» и выстраивает текстовые блоки сверху вниз. Текст рассчитывает свою высоту автоматически (в зависимости от длины слов). Браузер сам решает, где закончится заголовок и где начнется описание.
Шаг 2: Измерение и Привязка Спутников (Satellite Pass) Как только текст отрисован, система мгновенно считывает физические границы («коробку») каждого текстового блока на экране. Например, она видит: «Заголовок сейчас находится на высоте 340 пикселей от верха и имеет ширину 300 пикселей». После этого система берет «Спутники», находит те, что привязаны к Заголовку, берет их локальные смещения (например, «левее на 20px, выше на 10px») и приклеивает их в эти точки.
Результат: Если текст заголовка увеличился и сдвинул описание вниз, на Шаге 2 система увидит новые координаты описания и перерисует привязанный к нему стикер чуть ниже. Всё происходит за миллисекунды, пользователь не видит этой задержки.

3. Движок Координат (Virtual Canvas) — Масштабирование
Экран айфона имеет одно разрешение, экран Андроида — другое, а экспортировать картинку нам нужно в ультра-качестве (например, 1080x1920).

Если сохранять координаты в обычных пикселях экрана, то на разных устройствах всё поедет.

Решение: Система Виртуальных Координат (Virtual Space)

Внутри «мозга» системы холст всегда имеет фиксированный виртуальный размер (например, ровно 1000 х 1000 условных единиц).
Если стикер находится посередине, его координата в базе данных всегда X = 500, Y = 500.
Когда приложение запускается на телефоне, Движок Координат берет ширину экрана (например, 360 пикселей) и умножает координаты на коэффициент (360 / 1000 = 0.36). Стикер рисуется на отметке 180 пикселей.
При экспорте в высоком разрешении (например, 2000 пикселей) координаты умножаются на другой коэффициент (2000 / 1000 = 2). Стикер рисуется на отметке 1000 пикселей без потери качества.
4. Движок Жестов и Интерактивности (Gesture Processor)
Этот модуль обрабатывает касания пальцев на экране телефона и переводит их на язык математики.

Как работает перетаскивание (Drag & Drop):
Палец касается стикера. Движок фиксирует стартовую точку.
Палец движется. Движок высчитывает разницу координат (смещение) и двигает стикер вслед за пальцем.
Магнитный эффект (Snapping): В процессе движения система постоянно проверяет расстояние от стикера до границ текстовых блоков.
Если расстояние становится меньше, например, 30 виртуальных единиц, система включает «магнетизм»:
Она временно блокирует свободное движение.
Подает легкий импульс на вибромотор телефона (вибрация «тык»).
Визуально рисует пунктирную линию связи.
Если пользователь отпускает палец в этот момент, тип привязки в JSON автоматически меняется с Canvas на Flow (текст).
5. ИИ-Конвейер (The AI Pipeline) — Связь с Groq
Как именно происходит магия генерации, когда пользователь пишет: «Сделай афишу вечеринки в стиле техно»?

 [Ввод пользователя]
        │
        ▼
 [Конструктор Промпта] (Добавляет правила разметки, список доступных стикеров и стилей)
        │
        ▼
     [Groq] (Анализирует контекст, генерирует тексты и подбирает теги стикеров)
        │
        ▼
 [Семантический Матчер] (Ищет реальные картинки стикеров в нашей БД по тегам ИИ)
        │
        ▼
 [Сборщик JSON шаблона] (Собирает финальную структуру)
        │
        ▼
 [Отрисовка на экране]
Запрос: Пользователь вводит текст.
Обогащение промпта (System Prompt): Наш бэкенд берет этот текст и упаковывает его в техническую инструкцию для Groq. Мы передаем ИИ список наших стилей (например, "neon", "retro") и теги стикеров, которые у нас есть в базе (например, "star", "fire", "wine").
Ответ ИИ: Groq возвращает структурированный ответ: разделенный текст (заголовок, подзаголовок, дата) + выбранный визуальный стиль + список «намерений» для стикеров (например: «Я хочу добавить стикер с тегом "fire" и привязать его к заголовку справа»).
Связывание (Matching): Наша система видит намерение "fire", лезет в базу данных картинок, находит там, к примеру, файл cool_flame_sticker_v2.svg и подставляет его адрес в финальный JSON.
Рендеринг: Экран обновляется, пользователь видит готовую афишу со стильным стикером огня, который идеально прикреплен к заголовку.
Итог: почему эта схема жизнеспособна?
Разделение на Поток данных и Спутников-абсолютов позволяет держать систему в стабильности. Текст никогда не сломает верстку, потому что браузер рассчитывает его автоматически, а картинки и стикеры никогда не «улетят» за экран при смене телефона, так как они привязаны к тексту виртуальными координатами.


Вот универсальный, детальный список безликих стикеров для городской афиши. В описаниях нет привязки к стилю (3D, флэт, неоморфизм и т.д.) и культуре.
Везде используется только один переменный маркер цвета — «акцентный цвет» (вы сможете заменить его на любой нужный: красный, синий, зеленый, желтый и т.д. при генерации).
Категория 1: Информационные маркеры (База)
Гео-метка
Описание: Классический каплевидный пин (указатель карты). В центре пина вырезан минималистичный силуэт городского здания. Сам пин окрашен в акцентный цвет.
Календарь
Описание: Настольный перекидной календарь с открытой страницей. В центре страницы изображена крупная пятиконечная звезда, окрашенная в акцентный цвет.
Часы
Описание: Круглый циферблат часов без цифр, только с делениями. Две стрелки указывают вечернее время. Минутная стрелка окрашена в акцентный цвет.
Билеты
Описание: Два скрещенных входных билета прямоугольной формы со штрих-кодами и пунктирной линией отрыва. Один из билетов полностью окрашен в акцентный цвет.
Ценник
Описание: Вертикальный навесной ярлык для одежды со скругленными углами и круглым отверстием для веревочки вверху. На ярлыке изображен крупный знак валюты «₽», выполненный в акцентном цвете.
Категория 2: Рубрикатор (Направления событий)
Микрофон (Концерты)
Описание: Вокальный динамический микрофон на стойке-держателе. Кнопка включения на корпусе микрофона и декоративное кольцо на сетке окрашены в акцентный цвет.
Театральные маски (Спектакли)
Описание: Две маски, символизирующие трагедию и комедию, слегка перекрывающие друг друга. Маска комедии (улыбающаяся) полностью окрашена в акцентный цвет.
Диско-шар (Вечеринки)
Описание: Сферический зеркальный шар, подвешенный на тонкой цепочке. Несколько случайных зеркальных сегментов на шаре светятся акцентным цветом.
Хлопушка (Кино)
Описание: Приоткрытая режиссерская хлопушка-нумератор. Диагональные полосы на верхней подвижной планке хлопушки окрашены в акцентный цвет.
Палитра (Выставки)
Описание: Деревянная художественная палитра классической формы с отверстием для пальца. На палитре расположены три пятна нейтральной краски и одно крупное пятно акцентного цвета.
Лампочка (Лекции / Бизнес)
Описание: Классическая стеклянная лампочка накаливания. Металлический цоколь нейтральный, а нить накаливания внутри горит в форме светящейся шестеренки акцентного цвета.
Кроссовок (Спорт)
Описание: Современный спортивный кроссовок, показанный в профиль. Подошва и шнурки кроссовка окрашены в акцентный цвет.
Воздушный шар (Детские события)
Описание: Одиночный круглый надувной шарик на ниточке, устремленный вверх. Сам шарик полностью окрашен в акцентный цвет.
Категория 3: Интерактив и SMM (Призывы к действию)
Огонь (Популярное)
Описание: Стилизованный трехъязычный факел пламени. Самый крупный центральный лепесток пламени окрашен в акцентный цвет.
Закладка (Сохранить)
Описание: Вертикальная лента-закладка с раздвоенным нижним краем. В центре ленты изображен силуэт контурного сердечка, окрашенный в акцентный цвет.
Бумажный самолетик (Репост)
Описание: Сложенный из бумаги самолетик, летящий вверх под углом. За самолетиком тянется тонкая пунктирная линия шлейфа, окрашенная в акцентный цвет.
Восклицательный знак (Важно)
Описание: Равносторонний предупреждающий треугольник со скругленными углами. Внутри треугольника расположен крупный восклицательный знак, окрашенный в акцентный цвет.
Стакан кофе (Выходные)
Описание: Закрытый бумажный стаканчик для кофе на вынос с пластиковой крышкой. Защитный картонный манжет (воротничок) на стаканчике окрашен в акцентный цвет.
